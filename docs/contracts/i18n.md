# kenvoy 项目原生国际化

状态：参考；生效版本：Kenvoy CLI 0.3.0。国际化由 Kenvoy 配置、构建、交付和 Runtime 原生处理，不要求 kenvoy 项目安装 i18n 库、编写 Provider 或维护另一套语言状态。实施证据见 [0027](../changes/0027-native-project-i18n.md)。

完整可运行用法见 [i18n-app 报名示例](../../examples/i18n-app/README.md)：双语表单/后台、SDK 插值/复数/格式化、状态保留及已固化的初始迁移。

## 配置与接入

`kenvoy create customer-app` 默认生成中英文配置、业务词典和可运行的登记页：

```toml
[project]
name = "customer-app"
version = "1.0.0"
min_cli_version = "0.3.0"
format_version = "0.3.0"

[i18n]
default_locale = "zh-CN"
locales = ["zh-CN", "en-US"]
messages_dir = "locales"
```

显式 `[i18n]` 要求项目格式和最低 CLI 均不低于 0.3.0；不能只提高数字冒充已完成接入。CLI 支持格式范围为 `>=0.2.0, <0.4.0`。没有 `[i18n]` 的旧项目仍按单一 `zh-CN` 运行，不因存在同名目录自动启用国际化，也不出现语言切换器。

语言标识使用受校验的 BCP 47 形式，保留配置的大小写与顺序。默认语言必须精确出现在 `locales` 中，语言不能大小写重复。框架内置中文、英文系统文案；其他语言由项目提供词典，缺项按下文回退，不自动机器翻译。

`messages_dir` 相对项目根解析，可以位于 `src/locales`，不得与数据、输出、迁移、私有目录重叠，也不得包含 `target` 或 `.env*` 路径组件；解析后的链接目标同样受检。完整路径规则见[项目配置](project-configuration.md)。

## 词典与自动绑定

每种语言使用一个 `<语言>.json`，内容是平面字符串映射，不是嵌套对象：

```json
{
  "app.name": "Customer management",
  "resources.customers.label": "Customers",
  "resources.customers.fields.name.label": "Customer name",
  "resources.customers.fields.status.options.pending.label": "Pending",
  "pages./customers.title": "Customer registration",
  "text:请核对后提交": "Review before submitting",
  "custom.items.one": "{count} item",
  "custom.items.other": "{count} items"
}
```

DSL 中继续写正常的 `label`、`title` 等默认文本，不在声明中调用翻译函数：

```tsx
<resource name="customers">
  <text name="name" label="客户姓名" required />
  <select name="status" label="状态">
    <option value="pending" label="待确认" />
  </select>
</resource>
```

| 显示内容 | 原生词条键 |
|---|---|
| 应用名 | `app.name` |
| 资源显示名 | `resources.<资源>.label`，缺省为资源标识 |
| 字段标签 | `resources.<资源>.fields.<字段>.label` |
| 静态选项标签 | `resources.<资源>.fields.<字段>.options.<值>.label` |
| 页面标题 | `pages.<完整静态路径>.title` |
| 导航/分组标签、图片替代文本、普通文本及表单标签覆盖 | `text:<原文>` |

同一原文的 `text:` 词条有意共享，组件重排不改变词条身份。自定义组件的任意 props 不会被猜测成文案；需要翻译时使用 SDK 的 `custom.*` 词条。

资源名、字段名、路径、ID、选项值、默认值、条件、远程选项记录和业务记录不翻译。词典只控制显示，不改变授权、API 参数、数据库列、约束或 Schema 哈希。业务多语言内容的存储模型仍由应用业务声明决定，不将整条记录自动转换语言。

默认语言文件可以省略，由 DSL 默认文本和内置系统文案回退；非默认语言文件必须存在，可以显式为空词典。单条缺失允许回退。错误类型、重复键（包括转义后同名键）、不合法语言或路径、缺少整份非默认词典均明确失败，不忽略损坏词典。

## 语言选择与回退

选择优先级：已保存的 `kenvoy.locale` 偏好 → 浏览器语言（精确匹配后基础语言匹配）→ 项目默认语言；结果只能是项目明确支持的语言。多语言时框架自动显示可见标签的原生选择器；单语言隐藏。选择器可用键盘操作，`html.lang`、`dir`、页面标题同步更新，RTL 按语言文字方向处理。

查词顺序为当前语言项目词典 → 项目默认语言词典 → 当前语言族的内置系统词典 → 默认语言族内置词典 → 调用方默认文本 → 键本身。没有对应内置语言族时使用项目默认语言族，最终为中文。项目默认词典中的系统覆盖也参与回退，不能假定它会被英文内置文案越过。

`{name}` 是命名参数，`{count}` 可选择 `.one`、`.other` 等 `Intl.PluralRules` 分类；每一层回退按该词典实际语言选复数形式。参数作为文本处理，React 继续转义，不执行 HTML。

切换语言只修改客户端偏好，不重新加载页面、不重新取得 Session 或提升应用 generation，不重置未提交表单、自定义组件 Hooks、上传状态或当前身份。

## 自定义组件 SDK

```tsx
import { useI18n } from '@kenvoy/client';

export function Summary({ count }: { count: number }) {
  const { locale, t, formatNumber, formatDate, formatDateTime } = useI18n();
  return <section lang={locale}>
    <p>{t('custom.items', { count })}</p>
    <p>{formatNumber(1234.5)}</p>
    <p>{formatDate('2026-01-02', { dateStyle: 'long' })}</p>
    <p>{formatDateTime('2026-01-02T03:04:05Z', { dateStyle: 'long', timeStyle: 'short' })}</p>
  </section>;
}
```

Hook 还提供 `locales`、`setLocale`；复用框架上下文，不自行包 Provider。`t(key, params?, fallback?)` 的默认文本是第三个参数，不把插值参数写进键。

数字和日期使用缓存的 `Intl` 格式器，仅用于展示。`date` 要求合法 `YYYY-MM-DD` 并按 UTC 日历日解释；`datetime` 要求显式时区，显示默认 UTC，可通过格式选项明确指定时区。支持 `dateStyle/timeStyle`，不把它们与默认年月日组件混用。语言不代表时区。输入草稿和提交 JSON 继续使用规范数值、布尔、选项值和 ISO 日期，不把本地化千分位或阿拉伯数字写回数据库；记录 ID 保持原始标识。

原生 HTML 日期选择器内部的年月日占位、系统弹层及浏览器自身提示由浏览器/操作系统本地化；框架翻译字段标签、帮助、错误和记录展示，不宣称切换项目语言可以改写浏览器界面。自定义日期控件可复用同一字段绑定和 `useI18n()`，无需另建数据转换协议。

校验/API 错误保留原 `code`、`field`、`message`、请求关联标识，增加 `message_key` 和 `params`。界面据机器字段翻译，不解析中文消息反推规则；未知错误保留默认文本和核对编号。结果未知仍不可自动重试，不因翻译变成普通失败。

## 只读词条工具

```text
kenvoy --project customer-app i18n extract
kenvoy --project customer-app i18n extract --locale en-US
kenvoy --project customer-app i18n check
```

`extract` 向标准输出提供当前 DSL 默认文案和所选语言对应的内置系统默认词条，选项语言必须已配置；不自动翻译业务内容，不以旧词典覆盖当前 DSL，不覆盖文件或访问数据库。按需保存并审查后再合并翻译，避免覆盖已维护的业务词典。没有源码时从完整产物提取交付声明。

`check`（裸 `i18n` 也默认执行它）校验词典并输出 `status/default_locale/locales/missing`；`missing` 列出每种语言尚未显式覆盖的原生键。内置系统词条不算缺失；DSL 默认文本虽能回退，仍会在缺失清单中提示翻译覆盖。单条缺失不是退出失败；结构损坏、路径错误和整份非默认文件缺失才失败。普通 `kenvoy check` 同样校验词典。

## 交付、热更新与安全边界

词典进入构建输入指纹和产物格式 3 的私有 `i18n.json`，Manifest 独立绑定 i18n 配置摘要；完整 `dist` 配合匹配配置可无源码、无词典目录运行。HTTP 应用描述格式为 2，宿主 Application IR 仍为 1，Schema 哈希仍为 v1。新增文案不生成数据库迁移。

dev 把词典变化作为候选输入，与模型/脚本/资产同代验证和发布；损坏候选保留旧运行态。源码词典与产物私有文件不提供静态下载，浏览器描述只投影已授权页面、资源和字段对应的原生词条。`custom.*`、`ui.*`、错误覆盖等项目公共词条属于客户端内容，不得存放密钥、个人数据或服务端私有说明。

原生 i18n 不新增 Workspace 成员、不把业务职责放进 KEngine，也不改变正式迁移、旧库接入或开发快照之间的隔离规则。产物协议及无源码边界见 [Runtime](../architecture/runtime-design.md)，接口衔接见[客户端描述](application-ir.md)。
