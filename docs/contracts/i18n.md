# kenvoy 项目原生语言与集中译文

状态：参考；生效版本：Kenvoy CLI 0.4.0。国际化始终开启，没有关闭开关，也不要求应用安装 i18n 库或编写 Provider。当前契约替代 0.3.0 的可选 `[i18n]`、分语言文件和只读提取命令；实施证据见 [0028](../changes/0028-mandatory-languages-and-schema.md)。可运行用法见 [i18n-app](../../examples/i18n-app/README.md)。

## 语言配置

```toml
[project]
name = "customer-app"
version = "1.0.0"
min_cli_version = "0.4.0"
format_version = "0.4.0"

[languages]
fallback = "zh-CN"

[languages.zh-CN]
alias = "cn"
display = "简体中文"

[languages.en-US]
alias = "en"
display = "English"

[languages.ko-KR]
alias = "ko"
display = "한국어"
```

TOML 注释使用 `#`，不是 `//`。创建模板采用上述默认三语言；完全省略 `[languages]` 时也使用该默认配置，**不是关闭国际化**，仍须有合法 `translations.json`。显式配置只启用实际列出的语言，不自动补其他语言；单语言配置同样执行全部校验。

规则：

- 语言代码使用既有受限 BCP 47 形式，如 `zh-CN`、`en-US`、`ko-KR`、`ja-JP`；代码不能大小写重复。
- `fallback` 缺省为 `zh-CN`，必须精确等于已声明代码，不接受别名，不能由 CLI 猜测对应语言。
- 每个语言的 `display` 必填，不允许空或全空白；它是语言切换选项的显示文字，不由浏览器自动生成。
- `alias` 可省略；提供时必须是非空、非全空白字符串，不接受数组或多别名。别名全局唯一，不能与任何语言代码或别名大小写冲突；原始拼写保留。
- 没有语言、错误字段/类型、重复定义或非法 fallback 都是阻断错误，不降级成另一套隐式配置。

项目格式支持范围为 `>=0.4.0, <0.5.0`，最低 CLI 不得低于 0.4.0。旧 `[i18n]` 不再接受；升级先迁移配置、集中译文和交付文件，再显式更新兼容字段，不能仅改版本数字。

## 两个根目录文件

### translations.json

所有业务词条放入一个文件。顶层仅 `$schema` 必填，其余键由业务决定；`title`、`description`、`content` 不是框架硬编码字段。

```json
{
  "$schema": "./language.schema.json",
  "title": {
    "zh-CN": "产品名称",
    "en": "Product Name",
    "ko-KR": "제품명"
  },
  "description": {
    "cn": "这是一款产品",
    "en-US": "This is a product",
    "ko": "제품입니다"
  }
}
```

每个已存在的词条都必须提供全部配置语言的译文；每种语言只能选择其代码或别名中的一个，不能两者都写，也不能都不写。不同词条可以分别使用代码或别名。译文必须是长度至少为 1 的字符串，不能是空字符串、null、数字、数组或对象；不裁剪或改写译文内容。

未知语言键、重复 JSON 键（包括转义后相同）、漏语言、代码/别名同时出现都会失败。规范化后浏览器按语言代码查值；使用别名不会产生另一份语言状态。词典属于客户端内容，不得放入密钥、业务记录或服务端私有说明。

### language.schema.json

该文件由 `[languages]` 唯一生成，采用 JSON Schema draft 2020-12；可随应用提交版本管理，CLI 会按当前配置更新。顶层明确声明 `$schema` 为固定字符串 `./language.schema.json` 并列入 required，避免把这个元数据误作译文对象。

每个业务词条的 Schema 包含：

- `type: object`，`properties` 列出所有代码和别名，每项为 `string`、`minLength: 1`。
- `additionalProperties: false`，拒绝未知语言。
- `allOf` 为每种语言独立设置约束：有别名时使用两个 `required` 分支的 `oneOf`，保证代码或别名恰好一个；无别名时直接 required 代码。

根对象为 `minProperties: 1`，因此只有 `$schema` 的初始文件合法。Schema 不强制 DSL 全部词条，也不要求固定业务字段；新增词条时才完整检查其语言矩阵。JSON 原始重复键由解析器另行拒绝，不能依赖普通 JSON 对象在覆盖重复值之后才做 Schema 校验。

运行时使用固定 `jsonschema 0.33.0` 的实际 draft 2020-12 验证器，不凭编辑器提示判断正确性；禁用 HTTP/文件引用解析，不下载远程 Schema，也不相信被手改放宽的 language.schema.json。该版本避免为国际化全局启用 serde_json 的浮点解析新特性；升级验证器时须同时核查 Cargo feature 合并，不能连带改变业务 JSON 语义。

## 命令与启动检查

```text
kenvoy --project customer-app i18n
```

命令顺序：

1. 解析并检查 kenvoy.toml 的语言与兼容配置。
2. 生成最新 language.schema.json；字节未变则不重写，变化时原子替换，不允许链接或目录绕过固定文件边界。
3. translations.json 不存在时，用独占创建写入以下内容；存在时绝不覆盖或自动补译文。
4. 检查 `$schema` 引用，并用最新生成的 Schema 校验整个文件。错误给出文件/词条位置，退出非零。

```json
{
  "$schema": "./language.schema.json"
}
```

初始化不复制中文冒充其他语言，不编译 DSL、不执行应用函数、不连接数据库。报告包含 `schema_updated`、`translations_created`、fallback、语言定义及词条数。原 `i18n extract/check` 子命令已移除；普通 `kenvoy check` 仍只读验证源码与集中译文。

`dev`、`run` 同样先校验配置并更新 Schema，但**不创建 translations.json**。缺少该文件时明确提示执行 `kenvoy i18n` 或手工创建并引用 Schema；缺少/错误的 `$schema` 或内容不合法时在构建应用代码、创建数据库、迁移和对外服务之前停止。Schema 更新可以成功而译文校验失败，此时只更新派生 Schema，已有译文与业务库不变。

`build` 和 `check` 校验集中译文，不会因只有产物词典而忽略根文件。运行时不提供“跳过语言校验”选项。若部署目录需要更新 Schema，须具备相应写权限，不能把写入失败伪装成完成校验。

## 设备语言与页面切换

每次打开或刷新页面时读取设备默认 `navigator.language`，按规范代码大小写精确匹配已配置语言；读不到、无效或不支持时使用 fallback。不把 `en-GB` 猜成 `en-US`，不从其他浏览器偏好语言绕过不受支持的默认语言，也不让历史 localStorage 选择覆盖设备默认值。

页面内手动切换立即生效，控件选项显示配置的 `display`。SDK 的 `setLocale` 可传代码或别名，最终状态总是规范代码。切换不重载、不重新获取 Session、不提升 generation，也不重置草稿、上传或组件 Hooks。刷新后重新按设备默认语言选择；语言不决定时区。`html.lang`、`dir` 和页面标题同步更新，RTL 继续使用逻辑方向布局。

框架内置中文、英文系统文案；其他配置语言可通过集中词条覆盖系统键，没有覆盖的内置文案仍按 fallback 语言族回退。仅新增语言配置不等于已经提供该语言的全部系统翻译。

## DSL 自动键与自定义 SDK

DSL 继续使用普通默认文字，框架自动绑定以下键；没有对应业务词条时显示默认文字，不意味着国际化关闭。

| 显示内容 | 原生键 |
|---|---|
| 应用名 | `app.name` |
| 资源显示名 | `resources.<资源>.label` |
| 字段标签 | `resources.<资源>.fields.<字段>.label` |
| 静态选项标签 | `resources.<资源>.fields.<字段>.options.<值>.label` |
| 页面标题 | `pages.<完整静态路径>.title` |
| 分组/导航标签、图片 alt、文本及表单标签覆盖 | `text:<原文>` |

这些键作为 translations.json 顶层业务键，值仍是完整语言对象。原始 JSX 文本可能含空白，键按真实原文匹配。资源/字段/路径/ID、选项值、默认值、条件、远程业务标签和记录不翻译；自定义组件的任意 props 不自动猜作文案。

```tsx
import { useI18n } from '@kenvoy/client';

export function Product() {
  const { locale, t, setLocale, formatNumber, formatDate, formatDateTime } = useI18n();
  return <section lang={locale}>
    <h2>{t('title')}</h2>
    <p>{t('description')}</p>
    <p>{formatNumber(1234.5)}</p>
    <p>{formatDate('2030-05-20', { dateStyle: 'long' })}</p>
    <p>{formatDateTime('2030-05-20T10:30:00+08:00', { dateStyle: 'long', timeStyle: 'short' })}</p>
    <button type="button" onClick={() => setLocale('en')}>English</button>
  </section>;
}
```

`t(key, params?, fallback?)` 支持命名 `{name}` 参数及 `count` 对应的 `.one/.other` 等复数分类；每个出现的复数变体也是完整语言词条。参数作为文本转义，不执行 HTML。缺少整个业务键时依次使用内置文案、调用方默认文本或键本身，不在启动时强制生成假翻译。

数字/日期使用缓存 Intl 格式器，仅影响显示；日历日期是合法 `YYYY-MM-DD` 并以 UTC 日历日解释，datetime 必须显式带时区，显示默认 UTC。输入草稿及 JSON/SQLite 保持规范数值、布尔、选项值和 ISO 日期。原生 HTML 日期弹层和年月日占位由浏览器/操作系统本地化，项目语言不能改写浏览器界面。

字段/API 错误保留 code、field、message、HTTP 状态及请求关联标识，通过 message_key/params 翻译，不解析中文反推规则。网络结果未知仍须核对，不能因翻译变成可安全重试的失败。

## 构建、热更新与无源码交付

Application IR 仍为 1、Schema 哈希仍为 v1；词典变化不是数据库迁移。客户端描述为 3，词典 Bundle 为 2，产物格式为 4、输入/构建哈希为 v4。languages 配置、集中译文和规范化私有 i18n.json 进入构建身份；language.schema.json 是配置的派生文件，不进入源码输入指纹，不因自动刷新而自激热更新。

无源码部署需要 CLI、匹配的 kenvoy.toml、**translations.json**、完整 dist 和独立数据目录。language.schema.json 在启动时可重建，源码/migrations 目录不必保留；但根译文即使已有打包副本也不能缺失，规范化内容还必须与产物相同。无源码环境修改实际译文后须从对应源码重新构建，不能冒充原产物。

dev 重新检查语言配置、更新 Schema 并校验译文，完整候选与模型/资产/脚本同代发布；坏配置或译文保留最后有效运行态。HTTP 只投影当前身份可见原生词条，根译文、Schema 和产物私有词典不是静态资源。自定义公共词条仍属于浏览器内容，不得存放秘密。

本次没有新增 Workspace 成员或把业务职责放入 KEngine。正式迁移、数据库生命周期锁和开发快照规则保持，详见[运行时](../architecture/runtime-design.md)及[迁移操作](../operations/migration-design.md)。
