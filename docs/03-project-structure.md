源自设计会话确定的目标项目结构草案（Next.js 风格「文件系统即路由」），原文保留：

```text
项目结构
├── apps                # 所有应用都在如下目录，根下有仪表盘文件，然后再分多个应用，应用再分表单信息。
│   ├── dashbord        # 应用工作台说明页面
│   ├── 应用1           # 应用内容
│   │   ├── layout      # 应用根结构表单
│   │   ├── module      # 应用私有自定义组件（页面不需要有，如果是页面内的私有组件可以直接在页面内自定义了，如果是多页面私有就写在这里）
│   │   └── 页面        # 一个或多个页面
│   │       ├── page
│   │       ├── flow
│   │       ├── publish
│   │       ├── layout  # 可选
│   │       └── ...     # 其他细分内容
│   └── 应用2           # 结构同应用1
├── module              # 自定义通用组件（全局应用可共用自定义组件）
│   ├── 组件            # 表单、表格、图表等
│   └── 交互            # 按钮、提交、跳转等
├── I8n                 # 翻译应对表
│   ├── zh              # 中文内容
│   └── eng             # 英文内容
├── public              # 静态资源目录（项目访问该目录内容时直接走/路径请求即可（config 可配置访问路径，配置在项目下的调用路径可实际访问的映射路径，不可配置访问权限，内容和项目同级的公开访问内容，注意隐私） kenvoy cli 应该检查和项目的冲突性，静态资源目录不可在执行时修改，如上传文件时需走类似R2、S3或者sql的方式。）
├── dist                # 最终分发产物
├── docs                # 项目文档
├── packages            # 类似 node_modules 的外部库
├── kenvoy.toml         # 项目 config 配置文件（类似cargo.toml和package.json）
├── .kenvoy             # Kenvoy 本地元数据/缓存
├── .gitignore          # Git文件
└── .env                # 环境变量信息
```

> 注：`dashbord` 与 `I8n` 为原文拼写，保留原样。落地约定：数据模型文件位于 `apps/<应用名>/models.kenvoy.xml`（决策点 D1），见 [02-demo-plan.md](./02-demo-plan.md)。
